# Kopia Repository Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Data backups run in the two cases they could not: a command's output into a repository on a volume, and a volume on another node than its volume repository. For the time of the backup, the agent of the repository's node runs a kopia repository server, and kopia connects to it from where the data is.

**Architecture:**
- **Agent.** A new streaming RPC, `RepoServer`, has the agent run `kopia server start` on its own address, at a port the system picks, for as long as the stream is open. The agent's use case owns the process, its session directory and its stopping.
- **Backend.** The backend opens a session through `backupreposervice.OpenRepoServer`. It connects kopia with a new engine storage, `StorageServer`, and takes the backup in the backend (a stream) or through the agent of the data's node (a directory).
- **What does not change.**
  - Repositories on cloud storage, and directories on the repository's own node, are reached as today.
  - Deletes, syncs and cleanup run directly on the repository's node, as today.

**Tech Stack:** Go, gRPC with protoc (`protoc-gen-go` v1.36.12, `protoc` 7.35.1 made the committed code), kopia 0.23.1.

**Spec:** `docs/superpowers/specs/2026-09-27-kopia-repo-server-design.md`

## Review Focus

1. **Reaching the server across nodes.** The server listens on the agent's overlay address, at a port the system picks. The worker, and the agent of another node, must reach it over `local_net`.
   - A reasonable person expects the volume-on-another-node case to work on a multi-node swarm with its usual firewall: overlay traffic rides VXLAN, so no new port has to be opened.
   - Pinned by: Task 5, check 2.
2. **A backend that vanishes mid-backup** (the worker killed, its node lost).
   - The agent notices only through gRPC keepalive: the server pings after 1 minute of silence and waits 20 s. The kopia server then stops.
   - A reasonable person expects no `kopia server` left running for long.
   - Pinned by: Task 5, check 5, which kills the worker during a run and watches the process go within about 2 minutes.
3. **Two backups into one repository at once.** Two servers run, each on its own port, both setting the same user and password.
   - A reasonable person expects both to succeed.
   - Pinned by: `TestRepoServerUserPassword` (Task 4) for the password, and Task 5, check 3, live.
4. **The agent restarted during a backup.** The server dies with it, and the client's kopia fails.
   - A reasonable person expects the run to fail, saying the repository server stopped, and its retry to succeed.
   - Pinned by: `TestWithRepoServerClosesTheSession` (Task 4) for the message, and Task 5, check 6, live.
5. **The agent's memory during a large stream.**
   - A reasonable person expects it to stay near `GOMEMLIMIT` (256 MiB) plus the agent's own.
   - Pinned by: `TestRunKeepsTheServerForTheCallersTime` (Task 2), which checks `GOMEMLIMIT` reaches the server, and Task 5, check 7, which measures it.

## Decisions beyond the spec

These were taken while building the patches, and written back into the spec where they change it.

- **The agent answers with the port and fingerprint, not a URL.**
  - The backend sends the address it reached the agent by as `listen_host`.
  - The server listens there, on port 0.
  - The backend builds `https://<address>:<port>`.
  - kopia's generated certificate names 127.0.0.1 only. Pinning the fingerprint connects by any address, which was checked with kopia 0.23.1, and a wrong fingerprint is refused.
- **The session's client connects with `--no-persist-credentials`.** The password comes from `KOPIA_PASSWORD` on every command. Each session has its own config file, and `repository disconnect` removes it once the backup ends.
- **The server runs in its own process group,** and stopping it kills the group: nothing it started outlives it. It gets `SIGTERM`, then `SIGKILL` after 5 s.
- **The session directory** is `$TMPDIR/hivepaas/repo-servers/session-*`. It holds the config, the certificate and key, the cache and kopia's logs (`KOPIA_LOG_DIR`), and is removed at the end.
- **The control password** is random for each session and passed in `KOPIA_SERVER_PASSWORD`, never on the argv.
- **The backup requests gain `Progress func(string)`,** which the data backup runner writes into the run's log:
  - "Starting the repository server on node X";
  - "Repository server ready at <url>";
  - "Repository server stopped".
- **`checkRepoReachableFrom` goes,** replaced by `repoServerNeeded`. The agent executor's refusal of stdin stays as a guard that no flow reaches any more.
- **The agent use case reads its configuration when a session starts, not when it is built.** fx builds it before the configuration is loaded in some run modes.
